Conceitos básicos de banco de dados

Um banco de dados é uma coleção organizada de informações relacionadas entre si, guardadas segundo um padrão que permite localizá-las e manipulá-las com facilidade. Quando informatizado, ganhamos rapidez de acesso, compartilhamento entre vários usuários, regras de integridade e padronização.

BD informatizado vs. manual

Rapidez — milhões de registros em milissegundos via SQL otimizadas.

Multi-usuário — acesso simultâneo com controle de concorrência.

Segurança — permissões por perfil, criptografia, auditoria.

Integridade — regras automáticas contra dados inválidos.

Escalabilidade — cresce com o volume de dados.

Padronização — regras centralizadas.

SGBD — Sistema de Gerenciamento de Banco de Dados

O SGBD é o software que gerencia o banco de dados. Banco de dados é o conjunto de dados; SGBD é o sistema que o gerencia. São conceitos diferentes!

Modelos de banco de dados

Ao longo da história, diferentes modelos foram propostos. Hoje, o modelo relacional é o mais utilizado na indústria, mas os modelos NoSQL vêm ganhando espaço.

Foco deste guia: Modelo Relacional — utilizado pelo MySQL, PostgreSQL, SQL Server e Oracle. É o modelo exigido no mercado para a maioria dos sistemas transacionais.

Entidade, atributo e registro

AtributoCampo / colunanome, email, curso

Criando a tabela alunos no MySQL

CREATE TABLE alunos (
    id              INT AUTO_INCREMENT PRIMARY KEY,  -- Identificador único
    nome            VARCHAR(100) NOT NULL,            -- Obrigatório, até 100 caracteres
    email           VARCHAR(150) NOT NULL UNIQUE,     -- Obrigatório e único
    data_nascimento DATE,                            -- Formato AAAA-MM-DD
    curso           VARCHAR(50)  NOT NULL             -- Nome do curso técnico
);
Pontos de atenção: AUTO_INCREMENT gera o id automaticamente · PRIMARY KEY garante unicidade e não-nulo · NOT NULL impede campos vazios · UNIQUE impede e-mails duplicados.

Chave primária (PK)

Campo que identifica cada registro de forma única. Nunca se repete, nunca é nulo.

-- Chave primária simples (mais comum)
id INT AUTO_INCREMENT PRIMARY KEY

-- Chave primária composta (tabelas associativas)
PRIMARY KEY (aluno_id, disciplina_id)

Variações: simples (um campo), composta (ex.: agência + conta), única (não repete, mas pode ser nula), estrangeira (PK de outra tabela).

Chave estrangeira (FK)

Campo que referencia a PK de outra tabela, criando um relacionamento. Garante a integridade referencial: não é possível inserir um valor na FK que não exista na PK referenciada.

CREATE TABLE matriculas (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    aluno_id    INT NOT NULL,
    disciplina  VARCHAR(100) NOT NULL,
    ano         YEAR NOT NULL,
    FOREIGN KEY (aluno_id) REFERENCES alunos(id)
        ON DELETE CASCADE ON UPDATE CASCADE
);
No MySQL a FK exige indicar a coluna referenciada: FOREIGN KEY (aluno_id) REFERENCES alunos(id).

Relacionamentos entre tabelas

  • 1:1 — Um-para-um: pouco comum (ex.: Pessoa ↔ CPF).
  • 1:N — Um-para-muitos: o mais frequente (ex.: Cliente → Pedidos).
  • N:M — Muitos-para-muitos: exige tabela associativa intermediária (ex.: Pedido ↔ Produto via item_pedido).

Exemplo completo: sistema de pedidos

CREATE TABLE clientes (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    nome  VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);
CREATE TABLE produtos (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    nome  VARCHAR(100) NOT NULL,
    preco DECIMAL(10,2) NOT NULL
);
CREATE TABLE pedidos (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    cliente_id  INT NOT NULL,
    data_pedido DATE NOT NULL,
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);
CREATE TABLE item_pedido (
    pedido_id   INT NOT NULL,
    produto_id  INT NOT NULL,
    quantidade  INT NOT NULL DEFAULT 1,
    PRIMARY KEY (pedido_id, produto_id),
    FOREIGN KEY (pedido_id)  REFERENCES pedidos(id),
    FOREIGN KEY (produto_id) REFERENCES produtos(id)
);

item_pedido é a tabela associativa que resolve a relação N:M. Sua PK é composta pelos dois IDs estrangeiros. Note quantidade INT NOT NULL DEFAULT 1 — se não informado, o MySQL usa automaticamente o valor 1.

Integridade de dados

Integridade de domínio — valores válidos por coluna: NOT NULL, CHECK, DEFAULT, ENUM.

Integridade de entidade — unicidade garantida pela PRIMARY KEY; nenhum NULL permitido.

Integridade referencial — FK deve existir na tabela referenciada; ON DELETE RESTRICT / CASCADE controlam exclusões.

-- Exemplo de constraint CHECK no MySQL 8.0+
ALTER TABLE alunos
    ADD CONSTRAINT chk_nome CHECK (CHAR_LENGTH(nome) >= 3);

CRUD — INSERT, SELECT, UPDATE, DELETE

-- INSERT: inserir
INSERT INTO alunos (nome, email, curso)
VALUES ('Ana Silva', 'ana@email.com', 'Informática');

-- SELECT: consultar
SELECT id, nome, curso FROM alunos
WHERE curso = 'Informática' ORDER BY nome ASC;

-- UPDATE: alterar
UPDATE alunos SET email = 'ana.silva@senai.com' WHERE id = 1;

-- DELETE: excluir
DELETE FROM alunos WHERE id = 1;
Atenção: sempre use WHERE com UPDATE e DELETE. Sem ela, todos os registros serão afetados!

Normalização Aula 02

Normalizar é reorganizar os atributos de uma tabela para eliminar redundâncias, remover atributos multivalorados e evitar anomalias de inclusão, exclusão e alteração. O conceito foi formalizado por E. F. Codd a partir de 1970.

Problemas típicos de uma tabela não normalizada (EMPREGADO_DEPTO):

  • Cadastrar departamento sem empregado → campos em branco.
  • Excluir o único empregado → perde-se também o departamento.
  • Alterar nome do departamento → atualizar em todas as linhas.

Tabela não normalizada (TÑN)

TÑN
Proj(CodProj, Tipo, Descr,
     (CodEmp, Nome, Cat, Sal, DataIni, TempAl))

Dependência funcional

Uma coluna Y depende funcionalmente de X quando, sempre que X aparece, Y é o mesmo. Notação: X → Y.

TipoQuando ocorre
Total / completaDepende de toda a chave composta.
ParcialDepende de apenas parte da chave composta.
TransitivaDepende de outro atributo não-chave.

Primeira Forma Normal (1FN)

Todos os domínios contêm apenas valores atômicos — sem tabelas aninhadas.

1FN
Proj    (CodProj, Tipo, Descr)
ProjEmp (CodProj, CodEmp, Nome, Cat, Sal, DataIni, TempAl)

Segunda Forma Normal (2FN)

Estar na 1FN e todos os atributos não-chave dependerem totalmente da PK.

Atalho: se a PK é um único campo, já está na 2FN.
2FN
Proj    (CodProj, Tipo, Descr)
ProjEmp (CodProj, CodEmp, DataIni, TempAl)
Emp     (CodEmp, Nome, Cat, Sal)

Terceira Forma Normal (3FN)

Estar na 2FN e não conter dependências transitivas.

3FN
Proj    (CodProj, Tipo, Descr)
ProjEmp (CodProj, CodEmp, DataIni, TempAl)
Emp     (CodEmp, Nome, Cat)
Cat     (Cat, Sal)

4FN, 5FN e desnormalização

  • FNBC: versão mais rigorosa da 3FN.
  • 4FN: elimina dependências multivaloradas independentes.
  • 5FN: decomposição que só pode ser reconstruída juntando 3+ tabelas.

Desnormalização: juntar tabelas conscientemente para melhorar desempenho de leitura (comum em data warehouses).

Passo a passo: Proj → 3FN

DDL — criar e alterar tabelas

-- MySQL
CREATE TABLE Agencia (
    agencia_nome  VARCHAR(20) NOT NULL,
    agencia_cidade VARCHAR(30),
    ativos        DECIMAL(10,2),
    PRIMARY KEY (agencia_nome),
    CHECK (ativos >= 0)
);

-- Adicionar e remover colunas
ALTER TABLE agencia ADD COLUMN endereco VARCHAR(50);
ALTER TABLE agencia DROP COLUMN endereco;

-- Excluir tabela
DROP TABLE agencia;

Chaves e restrições de integridade

  • NOT NULL — impede valor em branco.
  • PRIMARY KEY — unicidade + não nulo.
  • UNIQUE — unicidade opcional.
  • CHECK — valida condição.
  • DEFAULT — valor padrão.
  • FOREIGN KEY — integridade referencial.
CREATE TABLE Conta (
    agencia_nome  VARCHAR(20),
    cliente_nome  VARCHAR(20),
    conta_numero  INT NOT NULL,
    saldo         DECIMAL(10,2),
    PRIMARY KEY (conta_numero),
    FOREIGN KEY (agencia_nome) REFERENCES Agencia (agencia_nome),
    FOREIGN KEY (cliente_nome) REFERENCES Cliente (cliente_nome)
);

INSERT INTO Agencia (agencia_nome, agencia_cidade, ativos)
VALUES ('Portão', 'Curitiba', 115000);

Exemplo aplicado: sistema bancário

Agencia  (agencia_nome, agencia_cidade, ativos)
Cliente  (cliente_nome, cliente_endereco, cliente_cidade)
Conta    (conta_numero, saldo, agencia_nome, cliente_nome)
Deposito (cliente_nome, conta_numero, valor)

Exercício 5 · Sistema de vendas

Construa um DER: cada venda tem vários produtos, um produto aparece em diferentes vendas. Cada venda é feita por um vendedor para um cliente. Produto fica em uma prateleira.

Exercício 6 · Administradora de imóveis

Condomínios formados por unidades. Cada unidade pode ter mais de um proprietário. Cada unidade tem no máximo um locatário. Normalize.

Exercício 7 · Alocação de equipe

Pessoas são alocadas a tarefas e recebem um equipamento. Crie o DER com cardinalidades e tabelas normalizadas.

Exercício 8 · Prática MySQL

Crie um banco de dados de biblioteca no MySQL com as tabelas: livros, autores, usuarios e emprestimos. Aplique PKs, FKs, tipos de dados corretos e constraints de integridade.
